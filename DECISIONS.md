# DECISIONS.md — Журнал архитектурных решений (ADR)

## ADR-001: Выбор Slint 1.9 со стилем `fluent` вместо Tauri / WebView2
- **Контекст:** Требуется лёгкое нативное Windows 11-приложение с минимальным потреблением RAM/CPU в фоне и единым портативным `.exe`.
- **Решение:** Использовать Rust + Slint 1.9 со встроенным Fluent-стилем (`with_style("fluent")`) и нативными цветами Mica.
- **Последствия:** Нет зависимости от системного WebView2 и Node.js; быстрый холодный старт и компактный бинарник.

## ADR-002: `reqwest` строго с `rustls-tls` без OpenSSL
- **Контекст:** Сборка под `x86_64-pc-windows-msvc` с OpenSSL требует установки Perl/NASM/vcpkg, что усложняет CI и локальную сборку.
- **Решение:** Настроить `reqwest` с `default-features = false` и фичами `["blocking", "json", "multipart", "rustls-tls"]`.
- **Последствия:** Полностью автономная компиляция на чистом Rust toolchain в GitHub Actions (`windows-latest`).

## ADR-003: Двухслойная архитектура `Core` + `AppModule`
- **Контекст:** В будущем к оболочке могут подключаться дополнительные модули (медиа-инструменты, стриминг-сервисы и др.).
- **Решение:** Ввести трейт `AppModule` и `ModuleRegistry` (`src/modules/mod.rs`), а также сканирование `./data/modules/`. Ядро отвечает только за окно, тему, трей, диагностику и агрегацию настроек/статуса.
- **Последствия:** Добавление нового модуля не требует переписывания жизненного цикла ядра.

## ADR-004: Выделенный Win32-поток для `tray-icon` и `muda`
- **Контекст:** В Slint-окне при скрытии в трей необходимо гарантировать обработку сообщений системного трея.
- **Решение:** Запускать системный трей в отдельном потоке со своим циклом `GetMessageW` / `DispatchMessageW` и обработчиками `TrayIconEvent::set_event_handler` / `MenuEvent::set_event_handler`, передающими действия через `slint::invoke_from_event_loop`.
- **Последствия:** Мгновенная реакция трея даже при свёрнутом UI и корректная очистка иконки через `PostThreadMessageW(WM_QUIT)`.

## ADR-005: Нативный Win32 Subclassing для Drag-and-Drop и Single-Instance Wakeup
- **Контекст:** Slint 1.9 не предоставляет встроенного колбэка на перетаскивание файлов из Проводника Windows и перехват кастомных сообщений от второго экземпляра процесса.
- **Решение:** В `src/main.rs` перехватывать `HWND` окна через `raw-window-handle`, вызывать `DragAcceptFiles(hwnd, TRUE)` и устанавливать `GWLP_WNDPROC` для обработки `WM_DROPFILES` и зарегистрированного сообщения `TorrServerUI_ShowWindow`.
- **Последствия:** Полноценный Drag-and-Drop `.torrent`-файлов из Проводника и корректное разворачивание из трея при повторном клике по `.exe`.

## ADR-006: Портативный конфиг `./data/` и автозапуск только через ярлык `.lnk`
- **Контекст:** Жёсткое требование 100% портативности без записи в реестр и `AppData`.
- **Решение:** Все пути вычисляются от `current_exe()`. Автозапуск реализуется созданием/удалением `.lnk` в пользовательской папке `Startup` через `WScript.Shell` (скрытый вызов PowerShell с `CREATE_NO_WINDOW`) только при явном включении тумблера.
- **Последствия:** Программу можно переносить на флешке без следов в системе.
