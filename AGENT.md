# AGENT.md — Регламент разработки для ИИ-агентов

Этот документ задаёт обязательные правила для любой ИИ-сессии, продолжающей разработку **TorrServerUI**.

## 1. Непреложные технические ограничения
1. **Язык и UI:** Rust (edition 2021) + Slint UI `1.9+` со стилем `fluent` (`slint_build::CompilerConfiguration::new().with_style("fluent".into())`).
2. **Без OpenSSL:** Любые HTTP-запросы выполняются через `reqwest` строго с `default-features = false` и фичами `["blocking", "json", "multipart", "rustls-tls"]`. Запрещено добавлять крейты, требующие системный OpenSSL на Windows.
3. **100% портативность:**
   - Категорически запрещено писать в реестр Windows или системные папки `AppData`.
   - Единственное допустимое исключение: создание/удаление ярлыка `.lnk` в папке Автозагрузки текущего пользователя только по явному включению тумблера автозапуска в Настройках.
   - Все пути вычисляются строго относительно директории запущенного `.exe` (`std::env::current_exe()`), данные хранятся в `./data/`.
4. **Автономные графические ассеты:** Иконки окна и системного трея генерируются программно в памяти (RGBA 32x32). Не добавлять обязательные внешние `.ico` / `.png` файлы в билд.
5. **Вывод кода без сокращений:** Запрещено оставлять `TODO`, `...`, заглушки или неполные функции. Любой редактируемый файл должен оставаться полностью компилируемым под таргет `x86_64-pc-windows-msvc`.
6. **Стилистика Windows 11 Fluent:**
   - Цветовая палитра строго по `ui/theme.slint` (Mica Light `#F3F3F3` / Dark `#202020`, акценты `#0067C0` / `#60CDFF`).
   - Скругления: `8px` для карточек, `SettingsExpander` и `PopupWindow`; `4px` для кнопок, полей ввода и элементов списков.
   - Шрифт интерфейса `"Segoe UI Variable"` (фолбэк `"Segoe UI"`), логов — `"Consolas"`.

## 2. Правила модульности (`Core` vs `Modules`)
- Ядро (`src/core/`) **не должно** содержать бизнес-логику конкретного модуля (`torrserver`). Взаимодействие с модулями идёт через трейт `AppModule` и `ModuleRegistry` (`src/modules/mod.rs`).
- Логика TorrServer, HTTP API, управление бинарником движка, плееры и буфер обмена изолированы в `src/modules/torrserver/` и `ui/modules/torrserver/`.
- Все важные события, ошибки и переходы состояний должны отправляться в шину диагностики (`src/core/diagnostics.rs`) с корректным тегом (`[CORE]`, `[TS:ENGINE]`, `[TS:API]`, `[TS:PLAYER]`, `[TS:UPDATER]`).

## 3. Обязательный протокол после внесения правок
После каждого изменения кода агент обязан:
1. Обновить `CHANGELOG.md` (раздел `[Unreleased]`) с описанием сделанных изменений.
2. Обновить `HANDOFF.md` (текущее состояние, что проверено, на что обратить внимание при следующей сборке).
3. При добавлении новых файлов или связей Slint ↔ Rust обновить `ATLAS.md`.
4. При принятии нового архитектурного решения добавить запись ADR в `DECISIONS.md`.

## 4. Чек-лист добавления нового модуля (Модуль №2, №3...)
1. Создать папку `src/modules/<module_id>/` с `mod.rs` и `ui/modules/<module_id>/`.
2. Реализовать для структуры модуля трейт `AppModule` (`src/modules/mod.rs`):
   - `info(&self) -> ModuleInfo`
   - `on_init(&mut self)`
   - `bind_ui(&self, ui: &AppWindow)`
   - `on_window_visibility_changed(&self, visible: bool)`
   - `on_shutdown(&mut self)`
   - `status_line(&self) -> ModuleStatus`
   - `diagnostics_snapshot(&self) -> String`
3. Зарегистрировать новый модуль в `ModuleRegistry::new(...)` (`src/modules/mod.rs`).
4. Добавить вкладки модуля в верхнюю часть боковой панели `NavigationView` в `ui/app.slint`, а его секцию настроек — в системную вкладку «Настройки».
5. Пробросить настройки модуля в `AppConfig` (`src/core/storage.rs`) с `#[serde(default)]` для обратной совместимости `config.json`.
6. Добавить тег модуля в вызовы `diagnostics::log_event(...)` и обновить `ATLAS.md`.
